How to Integrate Continuous Streaming into ad713x_fmc.c
================================================================

This shows how to modify your EXISTING ad713x_fmc.c to use
continuous streaming without creating a new main file.

================================================================

STEP 2: Add callback function (before main(), around line 85)
================================================================

/* Callback for processing captured data */
void process_adc_data(uint32_t *data, uint32_t num_samples, void *user_data)
{
	uint32_t i, j;
	float lsb = 8.192f / 16777216.0f;  /* 24-bit ADC */
	int32_t raw_value;
	float voltage;

	/* Process each sample */
	for (i = 0; i < num_samples; i++) {
		for (j = 0; j < AD4134_FMC_CH_NO; j++) {
			/* Extract 24-bit value */
			raw_value = data[i * AD4134_FMC_CH_NO + j];
			raw_value &= 0xFFFFFF00;
			raw_value >>= 8;

			/* Convert to voltage */
			voltage = lsb * (float)raw_value;
			if (voltage > 4.095f) {
				voltage = voltage - 8.192f;
			}

			/* YOUR PROCESSING HERE:
			 * - Save to file
			 * - Send over network
			 * - Calculate statistics
			 * - Perform DSP operations
			 */
		}
	}

	/* Optional: Print every 100th buffer */
	static uint32_t buffer_count = 0;
	buffer_count++;
	if (buffer_count % 100 == 0) {
		printf("Processed %u buffers (%llu samples)\n",
		       buffer_count, (uint64_t)buffer_count * num_samples);
	}
}

STEP 5: Customize the callback
================================================================

Edit the process_adc_data() function to:

1. Save to file:
   fwrite(data, sizeof(uint32_t), num_samples * 4, file_handle);

2. Send over network:
   udp_send(socket, data, num_samples * 4 * sizeof(uint32_t));

3. Perform FFT:
   arm_rfft_fast_f32(&fft_instance, float_data, fft_output, 0);

4. Calculate statistics:
   Track min/max/average for each channel

5. Trigger on threshold:
   if (voltage > threshold) trigger_event();


IMPORTANT NOTES:
================================================================

1. BUFFER SIZE: Default is 512K samples per buffer
   - Adjust in ad4134_continuous_streaming.h if needed
   - Larger = more processing time, more RAM

2. PROCESSING TIME: Must be < buffer fill time
   - At 1.176 MHz: 512K samples = 435ms fill time
   - Your callback must complete in < 435ms
   - Otherwise you get buffer overruns = data loss

3. MEMORY: Uses ~17MB RAM for 2 buffers
   - Make sure your Zynq has enough free RAM
   - Check via linker script

4. CACHE: Critical for DMA!
   - D-cache invalidation is handled automatically
   - Do NOT disable caches in main()
